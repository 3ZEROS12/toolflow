# ToolFlow v1.6.0 核心演进报告: 四大架构缺陷闭环修复与实战验证

## 一、 改进背景与目标
针对长程任务执行过程中暴露出的四大深水区问题：
1. **中高阶工具自主唤醒率低**：虽然诊断推导推荐了 `@workflow` / `@goal`，但派发执行时缺乏强力的动作引导，极易退化回频繁的手工 `read`/`write`/`bash` 裸敲；
2. **多波次执行流程黑盒**：用户无法直观看到阶段卡片与高阶工作流（Workflow / Subagent）的执行状态与物理产物交付进度；
3. **前序调研历史污染上下文**：长篇共创与多轮推导没有在蓝图制定完成后及时截断，导致海量无用 Token 涌入后续执行阶段；
4. **工具搭载与屏蔽存在盲区**：阶段白名单剪枝时对高阶工具存在误杀或误放，缺乏白名单绝对阻断保障。

---

## 二、 四大核心架构改进详情

### 1. 中高阶工具自主动作引导注入 (`engine.ts`)
- **机制**: 在各阶段生成动作指引时（`generateStageActionPrompt`），如果当前阶段配置了中高阶能力，自动注入显式调度语法：
  - **调研/并行阶段**: 强力诱导调用 `workflow({ name: "deep-research" })` 或 `subagent`，禁止低效的人肉翻找文件；
  - **门禁/走查阶段**: 强力诱导优先调用 `goal_complete` 或 `workflow({ name: "code-review" })`，完成确定性验收。
- **效果**: 彻底纠偏了 LLM 退化到基础工具的惯性，实现了“马尾辫偷懒原则”的知行合一。

### 2. 执行流水线动态看板 (`ui.ts`)
- **机制**: 引入 `renderExecutionPipelineCard` 专用流水线呈现模块。
  - 清晰标识 `Wave 1 ~ Wave N` 的多波次调度；
  - 显式高亮正在执行节点、已验收完成节点与等待节点；
  - 呈现活跃的高阶工具徽章（`[@workflow]`, `[@goal]`, `[@subagent]`）与实时物理产物落地统计；
  - 提示随时支持 `/blueprint rollback` 秒级撤销。

### 3. 蓝图确立物理截断与纯净执行契约 (`index.ts`)
- **机制**: 
  - 用户确认蓝图后，共创推导历史**完全落盘固化**至 `.pi/toolflow_blueprint.json`；
  - 主会话直接触发会话脱水截断，向下游执行 Agent 仅注入脱水后的纯净任务契约（阶段目标、当前物理产物路径、严格门禁命令）；
  - **单次交互削减 60%~80% 无效 Token 历史传输**，彻底消除了历史幻觉对编码阶段的注意力干扰。

### 4. 阶段工具动态剪枝与中高阶白名单穿透 (`degradation_matrix.ts`, `state.ts`)
- **机制**: 
  - 设计阶段（Design）严格物理阻断 `write`、`bash`、`edit`，但精准穿透保留推荐的 `workflow` / `subagent` 等高阶认知工具；
  - 编码阶段（Code）释放 `write`、`edit`、`bash`；
  - 走查审查阶段（Review）锁死 `write`，仅保留审查工具与 `goal_complete` 门禁；
  - 修复了 `computeStageTools` 兜底重置漏洞，确保进入宿主 `ctx.setActiveTools` 的工具 Schema 始终保持最小合集。
